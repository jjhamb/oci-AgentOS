Assignee Mapping logic

IF task.assignee == "default":
    specialist = _map_default_task_to_specialist(task.title, task.body)
    → Look for [ANALYST], [WRITER], [MARKETER], [CODER], [INFRA] prefix
    → Look for fallback keywords
    → Default: "analyst" (if no prefix matched)
    task.assignee = specialist   // remapped for pulsating logic

ELSE IF task.assignee in ("orchestrator", "infra"):
    → Drives Orchestrator tile directly (specialist tiles unaffected)

ELSE:
    → Pass through as-is (already a named specialist)

Only default-assigned tasks get remapped. This preserves the Kanban-only dispatch convention (all default → orchestrator → kanban → remapped to specialist for status).

6. Full Lifecycle Sequence (End-to-End)

Happy Path: Single Task

1. Capt Jhamb sends request → Orchestrator receives via chat
2. Orchestrator runs kanban_create() → task lands on kanban (assignee="default", status="ready")
   ├─ API detects non-done task → orch_pending_task = True
   ├─ Orchestrator tile: IDLE → PULSATING (violet, fast 2s pulse)
   ├─ Specialist tile: IDLE → PULSATING (if remapped)
   ├─ Radar: Center dot starts pulsing + specialist dot pulses
   └─ Tasks Panel: Card appears in READY column (amber border)

3. Dispatcher picks up task → status changes to "running"
   ├─ Orchestrator tile: PULSATING (continues)
   ├─ Specialist tile: PULSATING (continues)
   ├─ Radar: Expanding ring around specialist dot (most recent activity)
   └─ Tasks Panel: Card moves to RUNNING column (mint border)

4. Worker completes → kanban_complete() → status="done"
   ├─ Orchestrator tile: PULSATING → ACTIVE (solid glow, 10-min timer)
   ├─ Specialist tile: PULSATING → ACTIVE (solid glow, 2-min timer)
   ├─ Radar: Specialist dot stops pulsing (no expanding ring)
   └─ Tasks Panel: Card moves to DONE column (gray border)

5. 2 min later (specialist) / 10 min later (orchestrator)
   ├─ Specialist tile: ACTIVE → IDLE
   ├─ Orchestrator tile: ACTIVE → IDLE (if no new tasks)
   └─ Radar: Center dot returns to static violet

Blocked Path: Task Blocked

1. Task enters RUNNING → worker sets kanban_block(reason="...")
   ├─ API detects all non-done tasks are blocked → orch_all_blocked = True
   ├─ Orchestrator tile: PULSATING → ESCALATING (red, fast 1s pulse)
   ├─ Specialist tile: PULSATATING continues (still has non-done task)
   ├─ Radar: Center dot turns RED fast pulse (specialist dots unchanged)
   ├─ Dashboard: Red sticky banner appears at top of page
   ├─ Browser: Notification API fires (once per escalation episode)
   └─ Tasks Panel: Card appears in BLOCKED column (red border)

2. Orchestrator attempts kanban_unblock() OR creates new unblocking task
   ├─ If unblock succeeds → task returns to RUNNING
   ├─ orch_all_blocked recalculates → False (if any task now running/ready)
   ├─ Orchestrator tile: ESCALATING → PULSATING (violet resumes)
   ├─ Dashboard banner dismissed
   └─ Browser notification cleared on next poll

3. If Orchestrator cannot resolve → reports to Capt Jhamb via chat
   ├─ State remains ESCALATING until Capt Jhamb intervenes
   └─ Red pulse continues indefinitely (correct behavior—attention needed)
